### 项目细节
1. **数据去重标准**  
   在法律领域的NL2SQL任务中，我制定了三级去重标准：  
   - **语义级**：使用Sentence-BERT计算查询语句相似度（阈值≥0.95），过滤同义改写的查询（如“如何起诉”与“起诉流程”）。  
   - **结构级**：通过SQL解析器提取查询结构（如SELECT-FROM-WHERE子句），排除仅字段名不同但逻辑相同的SQL（如`WHERE id=1`与`WHERE id=2`）。  
   - **业务级**：结合法律专家建议，保留具有法律语义差异的相似查询（如“合同无效”与“合同可撤销”）。  
   *成果*：清洗后数据集减少32%冗余，模型训练速度提升25%。

2. **难度配比策略**  
   采用三维度难度评估体系：  
   - **查询复杂度**：基于SQL嵌套层数、聚合函数数量、JOIN表数量划分L1-L5级。  
   - **领域知识深度**：普通查询（如“法条查询”）vs 复合查询（如“结合XX法和XX条例的判决案例”）。  
   - **数据稀缺性**：低频法律场景（如“海事仲裁”）数据占比提升至20%。  
   *方法*：使用分层抽样，确保各难度区间F1分数均衡提升。


1. **One-Shot CoT Prompt设计**  
   - **设计思路**：参考法律推理的三段论（大前提-小前提-结论），构建“法条引用→事实分析→SQL生成”的思维链模板。  
   - **验证方法**：  
     - 对照组：普通指令微调（无思维链），模型在复杂查询上错误率42%。  
     - 实验组：One-Shot CoT微调，错误率降至28%（尤其在需要跨表关联的查询中提升显著）。  
   *案例*：对“同时涉及商标法和反不正当竞争法的案例查询”，思维链引导模型正确关联两个法律表，准确率从15%提升至62%。

2. **训练数据集量级调整**  
   - **调整依据**：  
     - 观察验证集上的Loss曲线，当Loss不再下降但未过拟合时，增加20%数据量。  
     - 使用主动学习筛选高不确定性样本（如模型预测置信度<0.6的查询）。  
   - **效果判断**：  
     - 引入“难度覆盖度”指标（各难度级别查询的准确率方差），理想方差<0.15。  
     - 最终数据集从8k扩展至12k时，复杂查询（L4-L5）准确率提升18%。

3. **多维度奖励函数设计**  
   - **新增维度**：  
     - **法律合规性**：通过法律知识库验证生成SQL是否违反强制性规定（如“不得查询未公开的个人隐私数据”）。  
     - **查询效率**：使用执行计划分析工具，奖励执行时间≤500ms的SQL（权重0.2）。  
   - **协同机制**：采用加权求和`R = 0.5R_match + 0.3R_legal + 0.2R_efficiency`，通过强化学习动态调整权重。

4. **GRPO微调 vs 有监督微调**  
   - **流程差异**：  
     - 有监督：固定数据集迭代训练，缺乏实时反馈。  
     - GRPO：通过奖励模型实时评估生成SQL，使用策略梯度更新生成器。  
   - **效果对比**：  
     | 指标         | 有监督微调 | GRPO微调 |
     |--------------|------------|----------|
     | 复杂查询准确率 | 58%        | 73%      |
     | 平均奖励分数   | 0.62       | 0.85     |
   - **难点**：奖励函数的稀疏性导致训练不稳定，通过引入课程学习（从简单查询到复杂查询逐步训练）解决。
